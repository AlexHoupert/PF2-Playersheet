# Catalog Pipeline

Last updated: 2026-06-16.

## Purpose

The repo ships a large local PF2e resource corpus in `ressources/`. The UI does not import most raw resources directly. Instead, Node scripts create compact JSON indexes in `src/data/`, and shared catalog modules decode those compact indexes for listing/filtering. Detail views fetch raw resource JSON on demand.

This keeps initial bundle size lower than importing full catalogs for every screen.

## Source Resource Layout

Largest source directories as of the scan:

- `ressources/icons`: about 10,644 files
- `ressources/bestiary`: about 6,791 files
- `ressources/feats`: about 6,690 files
- `ressources/equipment`: about 5,576 files
- `ressources/spells`: about 1,931 files
- `ressources/classfeatures`: about 841 files
- effect/glossary directories for feats, equipment, spells, bestiary, and families
- smaller `actions`, `conditions`, and `fonts` directories

The directory name is intentionally spelled `ressources` throughout the project. Do not rename it casually.

## Build Commands

Package scripts:

- `npm run build:shop`
- `npm run build:spells`
- `npm run build:feats`
- `npm run build:actions`
- `npm run build:impulses`
- `npm run build:creatures`

`npm run build` runs all data builds, then Vite, then copies `ressources/` to `dist/ressources/`.

## Runtime Catalog Modules

Shared modules under `src/shared/catalog/` decode generated indexes:

- `shopIndex.js`
- `spellIndex.js`
- `featIndex.js`
- `impulseIndex.js`
- `actionIndex.js`
- `abilityIndex.js`
- `creatureIndex.js`
- `shopRowMeta.js`

Typical pattern:

1. Import compact `src/data/*_index.json`.
2. Decode dictionary-coded arrays into plain item objects.
3. Export `*_INDEX_ITEMS`, filter options, lookup-by-name helpers.
4. Export `fetch*DetailBySourceFile` helpers for on-demand JSON fetch.

In dev, detail fetches use `/api/static`. In production, they use `/ressources`.

## Shop Pipeline Details

Files:

- Builder: `scripts/build_shop.js`
- Runtime: `src/shared/catalog/shopIndex.js`
- Admin view: `src/admin/ItemsView.jsx`
- Player shop: `src/player/ShopView.jsx`

Builder inputs:

- `ressources/equipment/**/*.json`

Builder outputs:

- `src/data/shop_catalog.json`
- `src/data/shop_index.json`

Important builder behavior:

- Converts PF2e coin objects into GP numbers.
- Derives hands from `system.usage.value`.
- Special-cases rune folders and usage to classify rune categories.
- Adds weapon damage, persistent damage, splash, range.
- Adds armor/shield stats.
- Injects virtual generic scrolls and wands for ranks 1-10/1-9.
- Produces dictionary-coded arrays plus separate weapon/armor side tables.

Runtime detail fetch:

- `fetchShopItemDetailBySourceFile(sourceFile)`
- Fetches `equipment/${sourceFile}` from static resources.
- Returns normalized item detail fields used by item modals and equipment logic.

## Creature Pipeline Details

Files:

- Builder: `scripts/build_creatures.js`
- Runtime: `src/shared/catalog/creatureIndex.js`
- Admin view: `src/admin/BestiaryView.jsx`
- Encounter view: `src/admin/EncounterView.jsx`
- Party screen: `src/player/PartyScreen.jsx`

Builder inputs:

- `ressources/bestiary/**/*.json`

Builder outputs:

- `src/data/creature_catalog.json`
- `src/data/creature_index.json`

`src/data/creature_catalog.json` is ignored in git. Runtime creature details are fetched from raw resource files through `fetchCreatureData(id)`.

## Spell/Feat/Impulse/Action Pipelines

Spells:

- `scripts/build_spells.js`
- `src/shared/catalog/spellIndex.js`
- Includes traditions, traits, level, school, time, range, defense, scroll/wand availability.

Feats:

- `scripts/build_feats.js`
- `src/shared/catalog/featIndex.js`
- Used by player and admin feat flows.

Impulses:

- `scripts/build_impulses.js`
- `src/shared/catalog/impulseIndex.js`
- Watch for existing debug logging in the builder.

Actions:

- `scripts/generate_action_index.js`
- `src/shared/catalog/actionIndex.js`
- Inputs are `ressources/actions`.

## Admin Rebuild API

File: `server/index.js`

Endpoint:

- `POST /api/admin/rebuild-index/:type`

Supported types:

- `spells`
- `impulses`
- `items` or `shop`
- `feats`
- `actions`
- `creatures` or `bestiary`
- `all`

The current `AdminApp.jsx` has a placeholder-ish `handleRebuild` that logs the request; if restoring UI rebuild behavior, wire it to this endpoint and surface status/errors.

## Change Guidance

- Do not manually patch compact index arrays unless debugging generated output.
- If a runtime list/filter field is missing, update both builder and decoder.
- If detail display is missing data, update the relevant `fetch*DetailBySourceFile` helper.
- If a resource path changes, update dev and production fetch assumptions.
- Rebuild the narrow catalog and inspect generated diffs before broad `build:data`.
